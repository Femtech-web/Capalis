# Capalis v0.1.0: agents that prove they're done

Describe a workflow in chat. Capalis compiles it into a Recipe you approve once. From then on, every write the Recipe makes is checked by reading it back.

**Highlights**
- **Full loop, live on real accounts:** a Discord bug report became an issue and a Slack notice, the reporter was told "tracked as #5", and when the issue was closed, "fixed and closed". All four writes were read back independently (run `75415396`). In the same session, a change to a capability quarantined the old version by itself.
- **Nothing runs unapproved.** Approval is a button for the owner, bound to the exact version shown. The model can't approve.
- **No duplicates, no blind retries.** Uncertain writes are reconciled by key, and "not found" only counts after a settle window.
- **Drift guard:** a changed token, permission or API shape quarantines the Recipe before it writes again.
- **For non-technical teams:** names instead of ids, button approval, `/capalis setup` with exact fixes, plain-text evidence, and alerts when something needs you.
- **Beyond engineering:**
  - Slack intake with threaded replies;
  - schedules;
  - a ready-made site watch;
  - other Hermes tools as approved read steps and checks.

**Install:** `hermes plugins install <owner>/<repo>#plugin`, then `hermes plugins enable capalis`. See [docs/USER_GUIDE.md](../USER_GUIDE.md).

**Requires:** Hermes Agent ≥ 0.23.0. No Python dependencies.

**Verification:** [JUDGES.md](../../JUDGES.md) lists every claim with the tests behind it and the dated results file.
