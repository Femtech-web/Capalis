# Capalis v0.2.0

**Teach your AI agent a job once. It does it every time, and proves every step.**

Capalis is a plugin for [Hermes Agent](https://github.com/NousResearch/hermes-agent). You describe a job in one sentence, for example "when someone posts a bug in #bugs, open an issue in my-app, tell #engineering, and keep the reporter updated." Capalis turns it into a **Recipe** and practices it once without sending anything. It runs only after you approve that exact version. Every action is read back from where it landed before it counts as done. Nothing is done twice, and the moment something it depends on changes, it stops and tells you.

v0.1.0 proved the loop works on real accounts. v0.2.0 makes it something a whole team can live with.

## What's new

### 📱 Your phone is the control panel
Connect Telegram, and Capalis messages you when a Recipe is ready for approval, when it has quarantined itself because something changed, or when a run needs you. Reply `/capalis approve`, read the step-by-step summary, and tap **Approve**. The button approves only the version you were shown, and the AI itself still can't approve anything.

### 🔔 Alerts that tell you what to do
One message per thing that needs a person, each with the exact command to type. Alerts survive restarts, are never sent twice, and don't flood you with history when first switched on. They go to Telegram, Slack or Discord.

### 💬 More places, more jobs
- **Slack intake:** reports in a Slack channel, with every reply in the report's thread.
- **Schedules:** recurring Recipes, run once per slot, with no pile-up after downtime.
- **Site watch,** a ready-made Recipe: "check my checkout page every 10 minutes and tell #ops if it's down."

### 🧩 Your other Hermes tools, safely
Any Hermes tool, built-in or from another plugin, can join a Recipe as a step or as an independent check:
1. The AI proposes a contract.
2. `/capalis contract test` makes one real call through Hermes.
3. You approve it with `/capalis contract approve`.

Change the contract and it needs approval again; revoke it and every Recipe that uses it stops.

### 🔍 No silent upgrades, easy audits
- A new version tells you exactly **what changed** before you approve it.
- `/capalis export <run>` writes a reviewer-ready evidence bundle in Markdown and JSON.
- Recipes can be shared between teams: exports are tamper-checked, and an import never carries an approval.

### 🛡 Fixed
- A reporter replying "thanks!" to Capalis's acknowledgement could have opened a second issue. Replies never start a run now.

## Proof
- **Live on real GitHub, Slack, Discord and Telegram accounts:** five verified runs.
  - **Approved from a phone** (run `57f7bd53`): Telegram delivered the approval request 9 seconds after the practice run, and the owner approved with a button. Then the full loop ran: issue #6 → team notice → "tracked as #6" → closed → "fixed and closed". All four writes were read back independently.
  - In the same session, a change to a capability quarantined the old version by itself (run `75415396`).
- **304 tests and 17 claims:** the tests pass, and every claim in [JUDGES.md](../../JUDGES.md) is regenerated from a real run and holds.
- **Catalog checks:** `hermes plugins validate` and `doctor` pass on Hermes v0.23.0.

## Upgrading from 0.1.0
Recipes approved under 0.1.0 are quarantined the first time 0.2.0 starts, because the capabilities they rely on changed version. That's the drift guard working as designed. Ask Hermes to rebuild the Recipe, then approve the new version; it takes about a minute.

## Install

```bash
hermes plugins install Femtech-web/Capalis#plugin
hermes plugins enable capalis
```

Then type `/capalis setup`, and follow the [quick start](../../README.md#quick-start) or the [owner's guide](../USER_GUIDE.md).
