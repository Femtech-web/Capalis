# Capalis v0.2.1

Security fixes from the Hermes plugin catalog review.

## What changed

- **Web checks only reach public addresses.** A web check's address is written by the model, and practice runs read for real. Localhost, private networks, cloud metadata (169.254.169.254) and other internal or reserved addresses are now refused three times: when the Recipe is built, before each request, and when connecting. The connection goes only to the address that was checked, so a changed DNS answer can't redirect it.
- **Only known read tools can be contracted:** Hermes's own `web_search` and `web_extract`. A contract is written by the model, so its "read-only" label can't be the proof. Tools that run commands, write, send or schedule are refused, and so are tools from other plugins.
- **You see a contract test's inputs before it runs.** `/capalis contract test` shows the exact tool and inputs, and calls it only when you confirm that version.
- **Practice runs never call a contracted tool.** Those steps are simulated, like writes.

## Upgrading from 0.2.0

Recipes approved under 0.2.0 are quarantined the first time 0.2.1 starts, because the capabilities they pin changed version. Ask Hermes to rebuild each Recipe, then approve the new version.

## Proof

- 328 tests pass on Python 3.11 and 3.13, including new tests for each fix.
- `hermes plugins validate` passes on Hermes v0.23.0.
